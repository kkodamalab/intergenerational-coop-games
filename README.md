# ふたりであそぼう！

シニアと子どもが2人で遊ぶ、秋の収穫とエアホッケー。TypeScript / Vite / Canvas 2D / PeerJS。

- リポジトリ：https://github.com/kkodamalab/intergenerational-coop-games
- 公開予定URL：https://kkodamalab.github.io/intergenerational-coop-games/
- 公開状態：この開発環境では公開先とGitHub APIへのアクセスが拒否されているため、Pagesの有効化・公開完了は未確認。

## Hostの起動

Node.js 24を使用します。

```sh
npm ci --cache /tmp/coop-npm
npm run dev
```

Hostのブラウザーで表示されたURLの `/intergenerational-coop-games/` を開きます。本番は上記Pages URLを開く構成です。ネットワーク越しのスマホ傾き操作にはHTTPSが必要です。ローカル開発のスマホ接続はHostのLAN IPでアクセスできる必要があります。

ゲームカードを選び、30 / 60 / 90秒、難易度、各プレイヤーの入力方式を設定します。STARTはスマホ2台が接続済みの場合、またはデモモードの場合に有効です。3秒後に開始します。PAUSE / RESUME、RESTART、HOME、FULLSCREENを利用できます。全画面表示はブラウザーの対応範囲に依存します。

## スマホ2台を接続

1. Hostでゲームを選択し、接続QRの表示を待ちます。
2. 1台目でプレイヤー1のQR、2台目でプレイヤー2のQRを読み取ります。
3. スマホのコントローラーを開き、Hostに2台とも「接続済み」と表示されるのを確認します。
4. STARTを押します。スマホの四角内をドラッグすると位置を操作できます。指を離しても位置を保持します。
5. 切断時はHostが一時停止します。スマホで「再接続」を押すか同じQRから開き直し、HostでRESUMEを押します。

スマホをロックせず、ブラウザーを前面に保ってください。入力が3秒途絶えると未接続として扱います。Hostを再読み込みすると接続IDが変わるため、新しいQRから接続してください。

## iPhoneの傾き操作

HTTPSの公開ページをSafariで開きます。「傾き操作を許可」を押し、iOSの権限ダイアログで許可します。ボタン操作から権限を要求します。最初の姿勢を中央として校正し、「中央に戻す」で再校正します。感度スライダーで調整できます。センサ入力を平滑化しています。権限拒否・非対応・センサ入力停止時はタッチ操作を利用できます。実機Safariでの権限と操作感は未検証です。

## デモモード

設定画面の「キーボードデモ」をオンにします。スマホ接続は不要です。

- プレイヤー1：W / A / S / D
- プレイヤー2：矢印キー

秋の収穫は2人の同方向操作で板全体を移動、上下差で傾きます。板は固定長の1枚です。栗10点、梨20点、柿15点。1秒保持して得点し、得点した果物は消えます。傾けると果物が転がり、端から落ちると失敗です。

エアホッケーはP1が下、P2が上です。それぞれ自陣の半分でパドルを操作し、相手ゴールに入れると1点。得点後は2秒待って中央から再開します。

## 通信と外部サービス

QRにはHostのPeer IDとプレイヤー番号を含むURLを埋め込みます。**QRだけでは通信しません。** PeerJS Cloud（`0.peerjs.com`）がHTTPS / WebSocketでシグナリングし、ブラウザー間のWebRTC DataChannelで正規化座標を送信します。参考にした既存リポジトリのPeerJS / QR / メタデータで入力枠を分ける構成に合わせています。参考リポジトリへの変更はありません。

インターネットとWebRTCを許可するネットワークが必要です。公開シグナリングサービスには可用性保証がなく、本アプリでは独自TURN中継を用意していません。会場のNAT・ファイアウォールによってはスマホ接続が成立しません。その場合はデモモードを使ってください。有料素材、研究データ保存、ログイン、ランキングはありません。イラストは自作Canvas図形と端末標準絵文字です。

## テスト

```sh
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

ブラウザーテストはローカルのPeerJSシグナリングサーバーを自動起動します。本番はこのサーバーを必要としません。

本環境のChromiumは別途npm経由で取得した実行ファイルを使用したため、検証時は `COOP_CHROMIUM=/tmp/chromium npm run test:browser` を実行しています。通常の環境ではPlaywright標準ブラウザーを使用してください。

確認済み：物理演算4件、ブラウザー3件、TypeScript / 本番ビルド。ブラウザーでは2コントローラーの同時接続、切断・再接続、タッチ保持、センサ権限要求の模擬処理、両ゲームのデモ・UIを確認しています。

未確認：iPhone実機、スマホ実機2台、公衆インターネット経由のPeerJS Cloud接続、会場ネットワーク、実際のGitHub Pages配信。

## GitHub Pages公開

`.github/workflows/pages.yml` はmainへのpushで物理テスト・ビルド後にPagesへ配信します。リポジトリの **Settings → Pages → Source → GitHub Actions** を選択する必要があります。環境からAPIが利用できるようになれば自動設定と配信状態の確認を再開できます。設定後、Actionsの「Test and deploy Pages」を再実行してください。

Viteのbaseは `/intergenerational-coop-games/`。コントローラーは同一ページのクエリを使うため、Pages上で別パスへの直接アクセスやSPAの404回避設定は不要です。
